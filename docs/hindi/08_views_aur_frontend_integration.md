# 08. व्यूज और फ्रंटएंड इंटीग्रेशन (Views & EJS Frontend)

---

## 1. `src/views/index.ejs` का अवलोकन

हमारे प्रोजेक्ट में फ्रंटएंड के लिए **EJS (Embedded JavaScript)** टेम्पलेट इंजन का उपयोग किया गया है। यह एप्लिकेशन एक आधुनिक **हाइब्रिड आर्किटेक्चर** पर काम करता है:
1. **सर्वर-साइड रेंडरिंग (SSR)**: जब यूजर पहली बार वेबसाइट खोलता है (`GET /`), तो नोड सर्वर HTML का मूल ढांचा रेंडर करके भेजता है।
2. **क्लाइंट-साइड API कॉल्स (CSR)**: इसके बाद ब्राउज़र में चल रही जावास्क्रिप्ट बैकएंड की REST API (`/api/todos`) को `fetch()` के जरिए कॉल करके डेटा लाती और बदलती है।

---

## 2. SSR बनाम CSR (Server-Side vs Client-Side Rendering)

### रियल-लाइफ उदाहरण: अखबार का छापाखाना बनाम स्मार्टफोन की स्क्रीन
- **SSR (EJS)**: जैसे सुबह का छपा हुआ अखबार। प्रेस में सारी खबरें पहले ही कागज पर छप जाती हैं और आपके हाथ में आते ही आप तुरंत पढ़ सकते हैं। (तेज शुरुआत, सर्च इंजन के लिए बढ़िया)।
- **CSR (React / Vue)**: जैसे स्मार्टफोन की स्क्रीन। पहले स्क्रीन चालू होती है, इंटरनेट से नया डेटा डाउनलोड होता है और फिर खबर दिखती है।
- **हमारा हाइब्रिड तरीका**: अखबार के पन्ने (मूल HTML) तुरंत खुलते हैं, और अंदर की खबरों के अपडेट (टास्क बनाना, डिलीट करना) बिना पेज रीलोड किए तुरंत लाइव होते रहते हैं।

### तुलना सारणी:

| विशेषता | SSR (EJS) | CSR (React / Single Page Apps) |
|---|---|---|
| **रेंडरिंग कहाँ होती है?** | Node.js सर्वर पर | यूजर के वेब ब्राउज़र में |
| **शुरुआती स्पीड (FCP)** | बहुत तेज (HTML तुरंत दिखता है) | धीमी (पहले बड़ी JS फ़ाइल डाउनलोड होती है) |
| **SEO (सर्च इंजन)** | बहुत बेहतरीन | बिना स्पेशल सेटअप के कठिन |
| **इंटरएक्टिविटी** | फॉर्म सबमिशन पर पेज रीलोड होता है | बिना पेज रीलोड किए स्मूथ अनुभव मिलता है |

## 3. EJS सिंटैक्स और सुरक्षा की समझ

EJS हमें HTML के अंदर ही जावास्क्रिप्ट कोड लिखने की सुविधा देता है। इसमें 3 सबसे महत्वपूर्ण टैग्स होते हैं:

| EJS टैग | नाम | काम | सुरक्षा (Security) |
|---|---|---|---|
| `<%= %>` | **Escaped Output** | वैल्यू को प्रिंट करता है और स्पेशल अक्षरों (`<`, `>`, `&`) को सुरक्षित HTML एंटिटी में बदल देता है। | **100% सुरक्षित**: XSS (Cross-Site Scripting) हमले रोकता है। |
| `<%- %>` | **Unescaped Output** | कच्चा (Raw) HTML कोड सीधे पेज पर छाप देता है। | **खतरनाक**: अगर यूजर के इनपुट पर इस्तेमाल किया, तो हैकर जावास्क्रिप्ट चला सकता है! |
| `<% %>` | **Scriptlet (लॉजिक)** | जावास्क्रिप्ट के लूप्स या इफ-एल्स (`if`, `for`) चलाने के लिए। यह कुछ भी प्रिंट नहीं करता। | सुरक्षित कंट्रोल फ्लो। |

## 4. ब्राउज़र में चलने वाला जावास्क्रिप्ट कोड (`fetch` API)

`index.ejs` के अंदर जावास्क्रिप्ट कोड लिखा है जो हमारी REST API से बात करता है:

### 4.1 सारे टास्क लोड करना (`GET /api/todos`)
```javascript
async function loadTodos() {
  try {
    const res = await fetch("/api/todos");
    const json = await res.json();
    if (json.success) {
      todos = json.data;
      renderTodos(); // DOM को अपडेट करता है
    }
  } catch (err) {
    showNotification("टास्क लोड नहीं हो सके", "error");
  }
}
```

### 4.2 नया टास्क बनाना (`POST /api/todos`)
```javascript
async function handleCreateTodo(e) {
  e.preventDefault(); // पेज को रीलोड होने से रोकता है

  const payload = {
    title: document.getElementById("titleInput").value,
    description: document.getElementById("descInput").value,
    status: document.getElementById("statusSelect").value,
  };

  const res = await fetch("/api/todos", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(payload),
  });

  const json = await res.json();
  if (json.success) {
    loadTodos(); // लिस्ट रीफ्रेश
  } else {
    showNotification(json.message, "error");
  }
}
```

### 4.3 सिर्फ स्टेटस बदलना (`PATCH /api/todos/:id/status`)
जब यूजर स्टेटस का ड्रॉपडाउन बदलता है, तो पूरे फॉर्म को दोबारा भेजने की जरूरत नहीं पड़ती। सिर्फ PATCH रिक्वेस्ट जाती है:
```javascript
await fetch(`/api/todos/${id}/status`, {
  method: "PATCH",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ status: newStatus }),
});
```

## 5. इंटरव्यू प्रश्न और उत्तर (Q&A)

### प्र. 1: `<%= %>` और `<%- %>` में अंतर क्या है और XSS अटैक से कैसे बचते हैं?
> **उत्तर**: `<%= %>` आउटपुट को HTML-escape करता है। उदाहरण के लिए, अगर किसी टास्क का नाम `<script>alert('hack')</script>` है, तो `<%= %>` उसे बदलकर `&lt;script&gt;` बना देता है, जिससे ब्राउज़र उसे स्क्रिप्ट के रूप में नहीं चलाता बल्कि साधारण टेक्स्ट की तरह दिखाता है। वहीं `<%- %>` बिना किसी रुकावट के कच्चा HTML डाल देता है, जिससे XSS (Cross-Site Scripting) हमला हो सकता है। इसलिए यूजर द्वारा दिए गए डेटा के लिए हमेशा `<%= %>` ही इस्तेमाल करना चाहिए।

### प्र. 2: फॉर्म में `e.preventDefault()` लगाना क्यों जरूरी होता है?
> **उत्तर**: पारंपरिक HTML फॉर्म्स का डिफ़ॉल्ट व्यवहार होता है कि बटन दबते ही वे पूरा पेज रीलोड करके सबमिट करते हैं। `e.preventDefault()` उस डिफ़ॉल्ट एक्शन को रोक देता है ताकि हम अपनी मॉडर्न जावास्क्रिप्ट के `fetch()` फंक्शन से बैकग्राउंड में चुपचाप API कॉल कर सकें और यूजर को बिना पेज रीलोड किए एक तेज और स्मूथ अनुभव मिले।
