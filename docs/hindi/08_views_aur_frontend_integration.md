## 2. केवल UI के लिए कैशिंग (Cache Only for UI, Not API)

अक्सर बैकएंड API को कैश करने से यूज़र्स को पुराना (Stale) डेटा दिखने लगता है। इस प्रोजेक्ट में **कैशिंग केवल UI लेयर तक सीमित रखी गई है**:

```text
┌─────────────────────────────────────────────────────────────┐
│                 क्लाइंट ब्राउज़र (Alpine.js UI)              │
│                                                             │
│   1. पेज लोड ──▶ लोकल UI कैश से तुरंत रेंडर                 │
│                 (localStorage: 'todo_ui_cached_items')      │
│                                                             │
│   2. UI सेटिंग्स कैश:                                        │
│      • चुना हुआ फ़िल्टर ('all', 'pending', आदि)             │
│      • सॉर्टिंग क्रम ('newest', 'oldest', 'title')          │
│      • ड्राफ्ट ऑटो-सेव (टाइप किया गया टेक्स्ट कभी गायब नहीं होता)│
└──────────────────────────────┬──────────────────────────────┘
                               │
            लाइव नेटवर्क फेच   │ (हमेशा सीधे डेटाबेस से डेटा लाता है,
            (GET /api/todos)   │  API पर कोई बैकएंड कैशिंग नहीं है)
                               ▼
┌─────────────────────────────────────────────────────────────┐
│              एक्सप्रेस 5 सर्वर और MySQL डेटाबेस             │
│                                                             │
│   • GET /api/todos    ──▶ हमेशा ताजा डेटाबेस रिकॉर्ड्स देगा  │
│   • POST /api/todos   ──▶ तुरंत डेटाबेस में सेव होगा         │
│   • स्टैटिक फाइल्स   ──▶ HTTP Cache-Control: max-age=86400  │
└─────────────────────────────────────────────────────────────┘
```

### केवल UI कैशिंग के 4 बड़े फायदे:
1. **जीरो-लेटेंसी स्क्रीन रेंडर**: जब यूजर दोबारा वेबसाइट पर आता है, तो उसे खाली स्क्रीन या लोडिंग का इंतजार नहीं करना पड़ता। लोकल स्टोरेज से पुराना डेटा पलक झपकते ही स्क्रीन पर दिख जाता है, और बैकग्राउंड में लाइव डेटा आते ही लिस्ट स्मूथली अपडेट हो जाती है।
2. **ड्राफ्ट ऑटो-सेव (Draft Persistence)**: अगर यूजर कोई लंबा टास्क लिख रहा था और गलती से मॉडल बंद हो गया या पेज रीलोड हो गया, तो उसका लिखा हुआ टेक्स्ट गायब नहीं होता (`Alpine.$persist`).
3. **फ़िल्टर और सॉर्ट की याददाश्त**: यूजर ने जो फ़िल्टर (जैसे 'Pending') चुना था, पेज रीलोड होने पर भी वही खुला रहता है।
4. **100% सटीक डेटा**: चूंकि API पर कोई कैश नहीं है, इसलिए नया टास्क बनते ही या डिलीट होते ही हर ग्राहक को हमेशा बिल्कुल फ्रेश डेटा ही मिलता है।

## 5. क्लाइंट-साइड कोड का विश्लेषण (`public/js/app.js`)

### 5.1 इनिशियलाइजेशन पर तुरंत कैश लोडिंग
```javascript
init() {
  const cached = localStorage.getItem("todo_ui_cached_items");
  if (cached) {
    this.todos = JSON.parse(cached); // पलक झपकते UI तैयार
    this.cacheHitOnLoad = true;
  }
  this.fetchTodos(); // बैकग्राउंड में असली डेटाबेस से फेच
}
```

### 5.2 स्टेटस बदलना (Optimistic Cycling)
जब यूजर स्टेटस बटन दबाता है, तो स्टेटस क्रम से घूमता है (`pending` -> `in_progress` -> `completed` -> `pending`):
```javascript
const nextStatusMap = {
  pending: "in_progress",
  in_progress: "completed",
  completed: "pending",
};
```
क्लाइंट तुरंत एक हल्का `PATCH /api/todos/:id/status` भेजता है, जिससे पूरा पेज रीलोड किए बिना स्टेटस तुरंत बदल जाता है।

## 6. इंटरव्यू प्रश्न और उत्तर (Q&A)

### प्र. 1: आपने API की जगह सिर्फ UI पर कैशिंग क्यों लगाई?
> **उत्तर**: बैकएंड API को कैश करने से डेटा असंगति (Data Inconsistency / Stale Data) का खतरा रहता है। यदि एक यूजर टास्क डिलीट करे और दूसरे यूजर को कैश्ड रिस्पांस मिले, तो गड़बड़ी हो जाती है। API को अन-कैश्ड रखने से MySQL से हमेशा 100% ताजा डेटा मिलता है। वहीं UI पर लोकल कैशिंग लगाने से यूजर को ऑफलाइन-फर्स्ट ऐप जैसी सुपरफास्ट स्पीड मिलती है और उसका लिखा हुआ ड्राफ्ट भी सुरक्षित रहता है।

### प्र. 2: Alpine.js में `[x-cloak]` का क्या महत्व है?
> **उत्तर**: जब तक Alpine.js की जावास्क्रिप्ट फ़ाइल डाउनलोड होकर इनिशियलाइज नहीं होती, तब तक `x-show="isModalOpen"` वाले मॉडल्स स्क्रीन पर अचानक फ्लैश (FOUC - Flash of Unstyled Content) हो सकते हैं। `[x-cloak] { display: none !important; }` लगाने से वे तब तक छिपे रहते हैं जब तक Alpine पूरी तरह लोड न हो जाए।

### प्र. 3: Express में स्टैटिक एसेट कैशिंग कैसे काम करती है?
> **उत्तर**: `src/app.js` में हमने `express.static(publicDir, { maxAge: "1d", etag: true })` लगाया है। यह ब्राउज़र को `Cache-Control: public, max-age=86400` हेडर भेजता है। जब यूजर दोबारा आता है, तो ब्राउज़र अपनी लोकल डिस्क से ही CSS और JS लोड कर लेता है, जिससे सर्वर पर लोड नहीं पड़ता और पेज तुरंत खुल जाता है।
