# 02. सर्वर बूटस्ट्रैप और लाइफसाइकल (Server & Bootstrap)

---

## 1. `src/server.js` क्या है और इसका काम क्या है?

`src/server.js` हमारे पूरे एप्लिकेशन का **स्टार्टिंग पॉइंट (Entry Point)** है। जब हम टर्मिनल में प्रोजेक्ट चालू करते हैं, तो Node.js सबसे पहले इसी फ़ाइल को चलाता है।

इसका काम है:
1. `.env` फ़ाइल से एनवायरनमेंट वेरिएबल्स (सीक्रेट पासवर्ड, पोर्ट, आदि) लोड करना।
2. डेटाबेस चालू है या नहीं, यह पहले ही चेक करना (Pre-flight check)।
3. ऑपरेटिंग सिस्टम के नेटवर्क पोर्ट (जैसे 3000) पर एक्सप्रेस सर्वर को लाइव करना (`app.listen`)।

यहाँ [`src/server.js`](file:///d:/node_project/todo-app/src/server.js) का पूरा कोड है:

```javascript
import "dotenv/config";
import app from "./app.js";
import db from "./config/db.js";

const PORT = process.env.PORT || 3000;

async function startServer() {
  try {
    await db.query("SELECT 1");

    app.listen(PORT, () => {
      console.log(`Server running at http://localhost:${PORT}`);
    });
  } catch (err) {
    console.error("Database connection failed:", err.message);
    process.exit(1);
  }
}

startServer();
```

## 2. एक-एक लाइन और कीवर्ड का गहरा विश्लेषण

### 2.1 `import "dotenv/config";`
- **क्या करता है**: यह रूट डायरेक्टरी की `.env` फ़ाइल को पढ़ता है और उसके सारे सीक्रेट्स को Node.js के ग्लोबल ऑब्जेक्ट `process.env` में भर देता है।
- **इसे सबसे ऊपर लाइन 1 पर क्यों लिखा गया?**: ES Modules (`import`) में Node.js कोड चलने से पहले सारे `import` स्टेटमेंट्स को ऊपर उठा लेता है (Hoisting)। अगर हम इसे लाइन 1 पर साइड-इफ़ेक्ट इम्पोर्ट की तरह नहीं लिखेंगे, तो डेटाबेस वाला मॉड्यूल (`db.js`) पहले ही लोड हो जाएगा और उस वक्त उसे पासवर्ड या यूजरनेम `undefined` मिलेगा।
- **रियल-लाइफ उदाहरण**: किसी फैक्ट्री में काम शुरू करने से पहले मेन पावर सप्लाई (जनरेटर) चालू करना ताकि सारी मशीनों को तुरंत करंट मिल सके।

### 2.2 `const PORT = process.env.PORT || 3000;`
- **क्या करता है**: यह चेक करता है कि क्या ऑपरेटिंग सिस्टम ने कोई पोर्ट नंबर दिया है? अगर हाँ, तो उसे ले लो, नहीं तो डिफ़ॉल्ट रूप से `3000` का उपयोग करो।
- **ऑपरेटर**: यहाँ लॉजिकल OR (`||`) का इस्तेमाल हुआ है। अगर बायाँ मान खाली या falsy है, तो दायाँ मान (`3000`) लिया जाएगा।
- **क्लाउड में इसकी जरूरत**: जब आप कोड को AWS, Render, या Heroku पर डिप्लॉय करते हैं, तो क्लाउड प्रोवाइडर खुद अपनी मर्जी का रैंडम पोर्ट नंबर `process.env.PORT` में देता है। अगर आप सिर्फ `3000` हार्डकोड कर देंगे, तो क्लाउड में आपका सर्वर क्रैश हो जाएगा।

### 2.3 `await db.query("SELECT 1");` (प्री-फ्लाइट चेक)
- **क्या करता है**: सर्वर चालू करने से ठीक पहले MySQL को एक बहुत छोटी सी पिंग क्वेरी भेजता है: `SELECT 1`।
- **यह क्यों सबसे बढ़िया प्रैक्टिस है?**: Node.js के कनेक्शन पूल बहुत आलसी (Lazy) होते हैं। जब तक कोई असली क्वेरी न चले, वे डाटाबेस से कनेक्ट नहीं होते। अगर MySQL बंद है और हमने यह लाइन नहीं लिखी, तो सर्वर चालू हो जाएगा और जैसे ही पहला ग्राहक आएगा, उसे एरर मिलेगी। `SELECT 1` चलाने से अगर डाटाबेस बंद है, तो सर्वर पहले ही सेकंड में क्रैश हो जाएगा (Fail-Fast)।
- **रियल-लाइफ उदाहरण**: हवाई जहाज़ उड़ाने से पहले पायलट कॉकपिट में सारे मीटर और इंजन चेक करता है। अगर इंजन में गड़बड़ है, तो यात्रियों को लेकर उड़ान भरने से पहले ही रनवे पर रुक जाना समझदारी है।

### 2.4 `process.exit(1);`
- **क्या करता है**: Node.js के रनिंग प्रोसेस को तुरंत बंद कर देता है।
- **`1` का क्या मतलब है?**: कोड `0` का मतलब होता है "सफलतापूर्वक काम पूरा हुआ"। कोड `1` का मतलब होता है "गंभीर गड़बड़ी (Fatal Error) की वजह से बंद हुआ"। Docker या Kubernetes जैसे टूल्स इस कोड `1` को देखकर अलर्ट भेजते हैं या कंटेनर को रीस्टार्ट करते हैं।

## 3. सीनियर इंटरव्यू स्पेशल: Graceful Shutdown क्या होता है?

इंटरव्यूअर आपसे पूछ सकता है: *"अगर सर्वर चलते हुए अचानक कोई रीस्टार्ट बटन दबा दे या Ctrl+C कर दे, तो जो 10 यूज़र्स उस वक्त डाटा सेव कर रहे थे उनका क्या होगा?"*

- **साधारण जवाब**: प्रोसेस तुरंत मर जाएगा और उनका डाटा करप्ट हो सकता है।
- **सीनियर डेवलपर का जवाब (Graceful Shutdown)**: हम OS के सिग्नल्स (`SIGTERM` और `SIGINT`) को पकड़ते हैं। नए कनेक्शन्स लेना बंद करते हैं, चल रही क्वेरीज़ को पूरा होने देते हैं, डाटाबेस पूल को प्यार से बंद करते हैं (`db.end()`), और फिर प्रोसेस एग्जिट करते हैं।

```javascript
process.on("SIGTERM", async () => {
  console.log("SIGTERM मिला! सर्वर को सुरक्षित बंद किया जा रहा है...");
  server.close(async () => {
    await db.end(); // पूल बंद किया
    process.exit(0);
  });
});
```

## 4. इंटरव्यू प्रश्न और उत्तर (Q&A)

### प्र. 1: `dotenv.config()` और `import "dotenv/config"` में क्या अंतर है?
> **उत्तर**: जब हम ES Modules (`"type": "module"`) इस्तेमाल करते हैं, तो सभी `import` स्टेटमेंट्स कोड एग्जीक्यूट होने से पहले ही रिजॉल्व हो जाते हैं। अगर हम `dotenv.config()` फंक्शन के रूप में लिखेंगे, तो हो सकता है कि उससे पहले इम्पोर्ट हुआ कोई दूसरा मॉड्यूल (जैसे `db.js`) चल जाए और उसे एनवायरनमेंट वेरिएबल्स न मिलें। `import "dotenv/config"` करने से यह गारंटी मिलती है कि सबसे पहले वेरिएबल्स लोड होंगे।

### प्र. 2: `startServer()` फंक्शन में `try/catch` लगाना क्यों अनिवार्य है?
> **उत्तर**: क्योंकि `await db.query("SELECT 1")` एक एसिंक्रोनस (Asynchronous) प्रॉमिस है। अगर डेटाबेस का क्रेडेंशियल गलत है या डेटाबेस सर्वर डाउन है, तो प्रॉमिस रिजेक्ट हो जाएगा। अगर `try/catch` नहीं होगा, तो Node.js में Unhandled Promise Rejection होगी। `catch` ब्लॉक में हम उस एरर को कंसोल पर साफ़-साफ़ दिखाते हैं और `process.exit(1)` करके अनस्टेबल प्रोसेस को तुरंत बंद कर देते हैं।
