# 04. रूटिंग और REST API डिज़ाइन (Routing & REST API)

---

## 1. `src/routes/todo.routes.js` का अवलोकन

रूटिंग लेयर का काम होता है कि वह बाहर से आने वाले URL पाथ और HTTP मेथड (जैसे GET, POST) को देखकर तय करे कि कौन-सा कंट्रोलर फंक्शन उस काम को पूरा करेगा।

यहाँ [`src/routes/todo.routes.js`](file:///d:/node_project/todo-app/src/routes/todo.routes.js) का पूरा कोड है:

```javascript
import { Router } from "express";
import {
  createTodo,
  getTodos,
  getTodoById,
  updateTodo,
  updateTodoStatus,
  deleteTodo,
} from "../controllers/todo.controller.js";

const router = Router();

router.post("/", createTodo);
router.get("/", getTodos);
router.get("/:id", getTodoById);
router.put("/:id", updateTodo);
router.patch("/:id/status", updateTodoStatus);
router.delete("/:id", deleteTodo);

export default router;
```

## 2. REST API के बुनियादी सिद्धांत

**REST** का फुल फॉर्म है **Representational State Transfer**। यह वेब सर्विसेज बनाने का एक मानक (Standard) तरीका है। REST में हम URL में किसी क्रिया (Verb) की बजाय रिसोर्स का नाम (Noun, जैसे `/api/todos`) लिखते हैं, और काम करने के लिए मानक HTTP मेथड्स का इस्तेमाल करते हैं:

| HTTP मेथड | रूट पाथ | काम | अपेक्षित स्टेटस कोड | Idempotent है? |
|---|---|---|---|---|
| **POST** | `/api/todos` | नया Todo टास्क बनाना | `201 Created` | **नहीं (No)** |
| **GET** | `/api/todos` | सारे Todo टास्क लाना | `200 OK` | **हाँ (Yes)** |
| **GET** | `/api/todos/:id`| किसी एक Todo को ID से लाना | `200 OK` / `404 Not Found` | **हाँ (Yes)** |
| **PUT** | `/api/todos/:id`| पूरे Todo को बदलना/अपडेट करना | `200 OK` / `404 Not Found` | **हाँ (Yes)** |
| **PATCH** | `/api/todos/:id/status` | सिर्फ टास्क का स्टेटस बदलना | `200 OK` / `404 Not Found` | परिस्थिति अनुसार |
| **DELETE**| `/api/todos/:id`| टास्क को डेटाबेस से डिलीट करना | `200 OK` / `404 Not Found` | **हाँ (Yes)** |

## 3. रियल-लाइफ उदाहरण: पोस्ट ऑफिस (डाकघर) की खिड़की

- **रिसोर्स (`/api/todos`)**: डाकघर का एक खास लेटर-बॉक्स डिपार्टमेंट।
- **POST**: नया पत्र डिब्बे में डालना। जितनी बार डालेंगे, डिब्बे में नए-नए पत्र बढ़ते जाएंगे (Non-Idempotent)।
- **GET**: पोस्टमास्टर से पूछना: "मेरे नाम के सारे पत्र दिखाओ" या "पत्र नंबर 5 दिखाओ"। सिर्फ देखने से पत्र में कोई बदलाव नहीं होता (Safe & Idempotent)।
- **PUT**: पुराने पत्र को निकालकर उसकी जगह एक नया सुधरा हुआ पत्र रख देना।
- **PATCH**: पुराने पत्र को छुए बिना बस उसके लिफाफे पर "अर्जेंट" या "पूरा हुआ" की छोटी सी मुहर लगा देना।
- **DELETE**: पत्र नंबर 5 को फाड़कर फेंक देना। एक बार फेंक दिया तो वह खत्म, दोबारा वही आर्डर देने पर भी नतीजा वही रहेगा कि पत्र मौजूद नहीं है (Idempotent)।

## 4. इंटरव्यू के सबसे हॉट टॉपिक्स

### 4.1 PUT और PATCH में असली अंतर क्या है?
- **PUT (`/api/todos/:id`)**: यह **पूरे रिसोर्स को रिप्लेस** करने के लिए होता है। अगर आप PUT में कोई फ़ील्ड छोड़ देते हैं, तो नियम के अनुसार उस फ़ील्ड को खाली माना जाना चाहिए।
- **PATCH (`/api/todos/:id/status`)**: यह **आंशिक बदलाव (Partial Update)** के लिए होता है। हमारे प्रोजेक्ट में जब यूजर टास्क को सिर्फ 'completed' मार्क करता है, तो हम पूरा टाइटल और डिस्क्रिप्शन दोबारा नहीं भेजते, बल्कि सिर्फ PATCH रूट पर नया स्टेटस भेज देते हैं।

### 4.2 Idempotency (आइडमपोटेंसी) क्या होती है?
अगर किसी API कॉल को एक बार चलाया जाए या 100 बार चलाया जाए, और दोनों स्थितियों में सर्वर का अंतिम परिणाम (State) बिल्कुल एक जैसा ही रहे, तो उसे **Idempotent** कहते हैं।
- **GET**: 10 बार चलाएं, डेटाबेस में कोई बदलाव नहीं होता।
- **DELETE**: ID 5 को पहली बार डिलीट किया, वह डिलीट हो गई। अब आप 99 बार और वही कॉल करें, डेटाबेस में ID 5 डिलीट ही रहेगी। परिणाम नहीं बदला।
- **POST Idempotent नहीं है**: अगर आप 10 बार `POST /api/todos` चलाएंगे, तो डेटाबेस में 10 अलग-अलग टास्क बन जाएंगे!

## 5. रूट पैरामीटर्स (`:id`) की बारीकियां

- जब हम रूट में `/:id` लिखते हैं, तो एक्सप्रेस इसे **डायनामिक पैरामीटर** बना देता है।
- अगर यूजर `/api/todos/25` पर जाता है, तो एक्सप्रेस `req.params.id = "25"` बना देता है।
- **सावधानी**: ध्यान रहे कि `req.params.id` हमेशा एक **स्ट्रिंग (String)** होता है, नंबर नहीं! इसीलिए हमारे कंट्रोलर में `parseId` फंक्शन का होना अनिवार्य है।

## 6. इंटरव्यू प्रश्न और उत्तर (Q&A)

### प्र. 1: `req.params`, `req.query`, और `req.body` में क्या अंतर है?
> **उत्तर**:
> - `req.params`: URL के पाथ से डायनामिक वैल्यू निकालता है (जैसे `/todos/:id` में से ID)।
> - `req.query`: URL के बाद लगे प्रश्नचिन्ह `?` से की-वैल्यू पेयर निकालता है (जैसे `/todos?status=completed&page=2` में से status और page)।
> - `req.body`: POST, PUT या PATCH में पेलोड के रूप में भेजा गया डेटा निकालता है (जिसे `express.json()` पार्स करता है)।

### प्र. 2: 200 OK और 201 Created में क्या फर्क है?
> **उत्तर**: `200 OK` तब भेजा जाता है जब कोई सामान्य रिक्वेस्ट (जैसे GET, PUT, DELETE) सफल हो जाती है। `201 Created` खास तौर पर तब भेजा जाता है जब किसी POST रिक्वेस्ट के कारण सर्वर पर एक बिल्कुल नया रिकॉर्ड (रिसोर्स) सफलतापूर्वक बन चुका हो।
